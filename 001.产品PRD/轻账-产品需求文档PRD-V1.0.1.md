## 二、V1.0.1 变更概述

### 2.1 背景

V1.0 版本为纯本地记账工具，应用打开即可使用，无身份概念。随着产品演进（V1.1 将引入共享账本、多端云同步），需要一个用户身份体系作为基础。V1.0.1 作为过渡版本，先行落地「用户注册登录」最小闭环，为后续多用户、云同步铺路。

### 2.2 版本目标

| 维度 | 目标 |
|------|------|
| **功能目标** | 用户可通过用户名+密码注册、登录、退出，未登录无法进入主功能 |
| **体验目标** | 登录态持久化，不频繁登录；退出后数据留在本地但入口关闭 |
| **技术目标** | 数据库升级到 v2，新增 users 表；密码安全存储；为 V1.1 多用户/同步预留身份字段 |
| **不做的事** | 不做手机号/邮箱注册、不做第三方登录、不做找回密码、不做服务端同步 |

### 2.3 版本范围边界

| 范围 | 说明 |
|------|------|
| ✅ 包含 | 用户名+密码注册、登录、退出、登录态持久化、路由守卫、错误提示 |
| ❌ 不包含 | 手机号/邮箱验证、第三方登录（微信/Apple）、忘记密码/找回、云端账号、多用户数据隔离 |

> **说明**：V1.0.1 的用户身份为「入口控制」性质，记账数据仍为本地全局共享，不按用户隔离。真正的多用户数据隔离将随 V1.1 共享账本一起落地。

## 三、功能需求

### 3.1 功能全景图（V1.0.1 增量）

```
轻账 V1.0.1
├── 📝 V1.0 全部功能（快速记账 / 分类 / 账户 / 报表 / 导出）
└── 👤 用户认证（新增）
    ├── 注册（用户名 + 密码）
    ├── 登录（用户名 + 密码）
    ├── 登录态持久化
    ├── 路由守卫（未登录拦截）
    └── 退出登录
```

### 3.2 功能详细说明

#### P0 —— 用户注册

| 字段 | 说明 | 规则 |
|------|------|------|
| **用户名** | 必填，唯一 | 2-20 字符，不可重复（大小写敏感），仅限字母/数字/中文/下划线 |
| **密码** | 必填 | 6-32 位，不限制字符类型（建议字母+数字） |
| **确认密码** | 选填 | 若实现则需与密码一致；V1.0.1 可省略 |

**交互流程**：

```
打开 App → 登录页 → 切换到「注册」Tab → 输入用户名 + 密码 → 点击「注册」
  ├─ 校验通过 → 注册成功 → 自动登录 → 进入首页
  └─ 校验失败 → 显示错误提示（用户名已存在 / 长度不符 / 密码过短）
```

**规则**：
- 用户名重复时提示「该用户名已被注册」
- 注册成功后**自动登录**，无需再次输入
- 密码使用 **SHA-256 + 随机 salt** 哈希后存储，不保存明文

---

#### P0 —— 用户登录

| 字段 | 说明 | 规则 |
|------|------|------|
| **用户名** | 必填 | 已注册的用户名 |
| **密码** | 必填 | 与注册时一致 |

**交互流程**：

```
打开 App（未登录）→ 登录页 → 输入用户名 + 密码 → 点击「登录」
  ├─ 校验通过 → 进入首页
  ├─ 用户不存在 → 提示「用户不存在」
  └─ 密码错误 → 提示「密码错误」
```

**规则**：
- 登录态持久化到 `localStorage`，刷新/重开浏览器保持登录
- 已登录用户访问 `/login` 自动跳转首页

---

#### P1 —— 路由守卫

| 场景 | 行为 |
|------|------|
| 未登录访问任意主功能页 | 重定向到 `/login` |
| 已登录访问 `/login` | 重定向到首页 `/` |
| 退出登录 | 清除登录态，跳转 `/login` |

---

#### P1 —— 退出登录

| 入口 | 说明 |
|------|------|
| 设置页「我的」→ 退出登录 | 显示当前用户名 + 退出按钮 |

**规则**：
- 退出仅清除登录态，**不删除本地记账数据**
- 退出后回到登录页

## 五、数据模型变更

### 5.1 实体关系（V1.0.1）

```
用户(User) ──1:N──> 账本(Book)    [V1.1 才真正关联]
用户(User) ──1:N──> 账目(Record)  [V1.0.1 暂不关联，全局共享]

V1.0.1 仅新增 User 实体，记账数据暂不按用户隔离。
```

### 5.2 新增数据表 —— users

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID | ✅ | 主键 |
| username | String(20) | ✅ | 用户名，唯一索引 |
| passwordHash | String | ✅ | 密码哈希值（SHA-256） |
| salt | String | ✅ | 随机盐（16 字节） |
| createdAt | Timestamp | ✅ | 注册时间 |

### 5.3 数据库版本升级

```
Dexie version(1) → version(2)
  新增 users 表：id, username（唯一索引）
  保留 records / accounts / categories 不变
```

### 5.4 密码存储方案

```
注册时：
  salt = 随机生成 16 字节
  passwordHash = SHA-256(salt + 原始密码)
  存储 { username, passwordHash, salt }

登录时：
  取出该用户的 salt
  计算 SHA-256(salt + 输入密码)
  与存储的 passwordHash 比较
```

> **安全说明**：SHA-256 + salt 可抵御彩虹表攻击。作为纯前端本地单机应用，此方案已满足场景需求；生产级服务端应用应改用 bcrypt/argon2，本版本不涉及。

## 七、交互与异常处理

### 7.1 校验规则汇总

| 场景 | 规则 | 提示文案 |
|------|------|----------|
| 用户名长度 | < 2 字符 | 用户名至少 2 个字符 |
| 密码长度 | < 6 位 | 密码至少 6 位 |
| 用户名重复 | 注册时已存在 | 该用户名已被注册 |
| 用户不存在 | 登录时查无此人 | 用户不存在 |
| 密码错误 | 哈希不匹配 | 密码错误 |
| 按钮禁用 | 用户名或密码为空 | 按钮置灰不可点 |

### 7.2 加载与反馈

| 状态 | 表现 |
|------|------|
| 提交中 | 按钮文案变为「处理中...」，按钮禁用 |
| 成功 | 直接跳转，无需 Toast |
| 失败 | 表单下方红底提示条，不跳转 |

## 八、非功能需求（增量）

| 维度 | 要求 | 说明 |
|------|------|------|
| **安全** | 密码 SHA-256+salt 哈希存储，不存明文 | 复用 V1.0 加密能力 |
| **性能** | 注册/登录响应 ≤ 500ms（含哈希计算） | 本地操作，无网络 |
| **持久化** | 登录态存 localStorage，刷新不丢失 | persist 中间件 |
| **兼容** | 需支持 `crypto.subtle` API（HTTPS 或 localhost） | 现代浏览器均支持 |
| **迁移** | V1.0 老用户数据保留，升级后首次进入跳登录页 | Dexie 自动迁移到 v2 |

## 十一、风险与对策

| 风险 | 等级 | 影响 | 对策 |
|------|------|------|------|
| 用户忘记密码无法找回 | 🟡 中 | 账号不可用 | V1.0.1 暂不处理，文档提示「请妥善保管密码」；V1.1 考虑本地重置 |
| 公共设备登录态泄露 | 🟡 中 | 数据被他人查看 | 登录页底部安全提示；建议退出登录 |
| 清浏览器数据丢失登录态 | 🟢 低 | 需重新登录 | 可接受，重新登录即可 |
| `crypto.subtle` 在非 HTTPS 不可用 | 🟢 低 | 注册登录失败 | 本地/localhost 可用；部署需 HTTPS |
| 老用户升级后数据如何归属 | 🟢 低 | 数据无主 | V1.0.1 全局共享，V1.1 再迁移关联 |
